# DS18B20 温度实时显示（单总线 + OLED + 串口）

基于 **STM32F103C8T6 + STM32F10x 标准外设库（SPL）** 的温度采集工程：用软件模拟 1-Wire 时序读取 DS18B20，OLED 显示当前 / 最高 / 最低温度，同时通过 USART1 把温度打印到串口助手。

## 功能

- DS18B20 采用 **12 位分辨率**（0.0625℃），每次转换最长 750ms，主循环约 1 秒刷一次；
- 读取时做 **Dallas CRC8 校验**，校验失败会显示 `ERR` 而不是显示错误温度；
- OLED 四行显示：`温度:` 当前值 / `MAX:` 历史最高 / `MIN:` 历史最低 / 状态；
- 串口 **115200-8-N-1** 输出 `T=25.6C MAX=... MIN=...`，可直接对照看数据；
- 没接传感器时状态行显示 `ERR`，串口打印错误码（1 = 无应答，2 = CRC 错），便于排查接线。

## 硬件连接

| DS18B20 / 模块 | STM32F103C8T6 | 说明 |
|---|---|---|
| VDD（红色） | 3.3V | 模块一般 3.3~5V 都行，接 3.3V 与 IO 电平一致最稳 |

| DQ（黄色/白色） | **PB12** | 单总线数据线；模块板载上拉，裸器件需在 DQ 与 3.3V 间接 **4.7kΩ** 上拉 |

## 工作原理（为什么这么写）

1. **单总线只有一根数据线**，主机和从机都只能“拉低”或“释放”，所以 DQ 必须配成 **开漏输出**（`GPIO_Mode_Out_OD`），由上拉电阻负责把线拉高；推挽输出会和从机对拉，通信必挂。
2. 通信靠**时隙宽度**区分 0/1：
   - 复位：拉低 ≥480µs，释放后 15~60µs 内从机回一个 60~240µs 的低电平（存在脉冲）；
   - 写 1：拉低 1~15µs（本工程 2µs）后释放；写 0：拉低 60~120µs；
   - 读位：拉低 2µs 后释放，10µs 左右采样，再补满 60µs；
   - 全部用 `Delay_us()`（SysTick，前提系统时钟 72MHz）拼出来，时序容差约 ±10µs。
3. 一次测温的指令流程：`复位 → 0xCC(Skip ROM，总线上只有一片) → 0x44(启动转换) → 等 750ms → 复位 → 0xCC → 0xBE(读暂存器 9 字节) → CRC8 校验 → 换算`。
4. 换算：暂存器前两字节组成 12 位有符号数，最低 4 位是 1/16℃，所以 `℃ = raw / 16`；本工程先乘 10 再四舍五入，直接得到 0.1℃ 单位的整数，显示时再拆成“整数位 + 小数点 + 小数位”。

## 本工程实际用到的代码

| 文件 | 内容 |
|---|---|
| `Hardware/DS18B20.c` / `.h` | `DS18B20_Init()` 配引脚；`DS18B20_Reset()` 复位并检测应答；`DS18B20_ReadTemp()` 转换 + 读取 + CRC + 换算 |
| `Hardware/Serial.c` / `.h` | `Serial_Init()` 配 USART1；重定向 `fputc`，可直接用 `printf` |
| `User/main.c` | 初始化 → 主循环读取温度 → OLED 刷新 → 串口打印 |

`Library/`、`Start/`、`System/` 及 `Hardware/` 下其余驱动都是模板自带文件，本工程未调用。

## 常见问题

| 现象 | 可能原因 |
|---|---|
| 状态一直是 `ERR`，串口错误码 1 | DQ 接错脚 / 没共地 / 没上拉电阻 / 引脚宏和实际接线不一致 |
| 读数偶尔跳变、CRC 错 | 杜邦线太长或没上拉（超过 1m 建议 4.7k 上拉并缩短线），或系统时钟不是 72MHz 导致 `Delay_us` 偏差 |
| 上电第一帧显示 85.0℃ | DS18B20 上电默认寄存器值就是 +85℃，属于正常现象；第一次转换完成后即恢复真实温度 |
| 温度一直是同一个值 | 主循环被别的东西卡住（本工程读温度会阻塞 750ms），或没调用 `DS18B20_Init()` |
| OLED 花屏 | 上电先 `OLED_Init()` 再 `OLED_Clear()`，本工程已按此顺序 |
